# 🔗 Projeto Azure Data Factory + Azure DevOps

Este projeto demonstra como integrar o **Azure Data Factory** ao **Azure DevOps**, permitindo **versionamento**, **controle de mudanças** e **backups automáticos** de pipelines e artefatos de dados.  
A integração garante maior **governança** e **rastreabilidade** no desenvolvimento de soluções de dados, além de preparar o ambiente para futuras automações de **CI/CD**.

---

## 🎯 Objetivos do Projeto
- Configurar a integração entre **Azure Data Factory** e **Azure DevOps**.  
- Versionar pipelines e artefatos de dados em repositórios Git.  
- Garantir governança e rastreabilidade no ciclo de desenvolvimento.  
- Aplicar boas práticas de configuração e organização.  
- Preparar a esteira para automações de CI/CD no Azure.  

---

## 🏗️ Etapas do Projeto

### 1. Criação da Organização e Projeto no DevOps
- Configuração inicial no **Azure DevOps**.  
- Criação de uma organização e projeto dedicado.  

### 2. Configuração do Repositório Git
- Criação de repositório Git no DevOps.  
- Definição de **branches** (ex: `main`, `develop`, `feature`).  
- Conexão direta com o **Azure Data Factory**.  

### 3. Integração com Data Factory
- Configuração da integração durante ou após a criação do recurso.  
- Publicação de pipelines e datasets diretamente no repositório.  
- Visualização e gerenciamento dos arquivos versionados.  

### 4. Boas Práticas
- Padronização de nomenclatura de pipelines e datasets.  
- Organização de branches para diferentes ambientes (dev, test, prod).  
- Backups automáticos e versionamento contínuo.  

### 5. Preparação para CI/CD
- Estruturação da esteira de automação.  
- Configuração inicial para futuras pipelines de **CI/CD**.  

---

## ⚙️ Tecnologias Utilizadas
- **Microsoft Azure**
- **Azure Data Factory**
- **Azure DevOps**
- **Git**
- **CI/CD Pipelines**

---

## 🚀 Como Reproduzir
1. Crie uma organização e projeto no [Azure DevOps](https://dev.azure.com).  
2. Configure um repositório Git e defina branches.  
3. No **Azure Data Factory**, conecte o recurso ao repositório.  
4. Publique pipelines e datasets para versionamento automático.  
5. Visualize e gerencie os arquivos diretamente no DevOps.
